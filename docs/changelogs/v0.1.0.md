# Changelog — v0.1.0

Every addon still reports `version = "0.1.0"` (`CfgPatches`, all ten PBOs) — no version bump or
tag has been cut yet, so this file covers the whole of development to date under that one version.
Entries are sourced directly from the real git history (`git log`), newest first, one section per
day of activity. When a later version ships, it gets its own `vX.Y.Z.md` file in this folder.

## 2026-10-23 (Zeus modules actually placeable, dialog state bugs, multi-module sync, session auto-prune)

**Fixed**
- **Zeus modules (Spawn Patient, MCI Spawner, Edit Injuries) couldn't actually be placed at all** —
  root cause confirmed directly from a real RPT line ("Cannot create entity with abstract type
  AFCM_SIM_ModuleMciSpawner (scope = private?)"), not guessed: all three had `scope = 0` ("private"),
  which blocks real object instantiation at the engine level — a separate, deeper gate than
  `scopeCurator`'s own Zeus-browser-listing check. They could be selected from the browser, but every
  placement attempt silently failed at creation, so the module's own function was never reached —
  explaining why two earlier rounds of static code review on the function files themselves found
  nothing wrong (the bug was never there). Fixed by using `scope = 1` ("protected") instead, which
  still hides them from Eden's own placement browser but allows real instantiation. *(`b636e1f`, PR
  #59; diagnosed via `0dc6568`/`7cc66b1`, PR #46/#56)*
- **Spawn Session auto-prune, in two passes.** Sessions weren't being removed once every patient in
  them was gone unless cleared via this mod's own Session Manager — a patient deleted any other way
  (Zeus's own delete/trash tool, a scripted `deleteVehicle`) never told the session bookkeeping it was
  gone. Fixed with a per-patient `"Deleted"` event handler (a real vanilla entity event, not a kill —
  fires for a direct Zeus delete too). *(`be6d357`, PR #54)* A retest then found this still failed for
  a multi-select batch delete: several patients in the same session deleted simultaneously each saw
  the others as `!isNull` at that exact instant (their own deletions hadn't "landed" to each other's
  checks yet), so every check — including the very last one — still thought survivors remained. Fixed
  by having each deletion explicitly remove itself from the session's tracked list instead of polling
  `isNull` on units whose own deletions might not have reached this one's handler yet. *(`9c66cf2`, PR
  #60; diagnosed via `567b343`, PR #58)*
- **Multiple AFCM Patient modules synced to the same object collided.** The synced object tagged the
  triggering module's logic reference under one shared variable key, so a second module synced to the
  same object silently overwrote the first's. Every spawn interaction on that object then resolved to
  whichever module synced most recently, no matter which "AFCM: Spawn \<Title\>" label was actually
  clicked — reported directly: two modules synced to one object (Airway Management + Limb Injuries)
  only ever spawned the Airway preset. Fixed by keying storage per module (`netId`-derived) and baking
  that key into each module's own compiled statement code. *(`35541ee`, PR #53)*
- **Interactive Terminal's Zeus "drag onto an object" path hardened** — it checked `attachedTo _logic`
  exactly once, 1s after firing, and gave up silently if that single attempt landed too early for
  replication. Now retries every 1s for up to 5 attempts, with every attempt logged. *(`1152fb4`, PR
  #55)*
- **Injury Author reopened on a patient still didn't show their current injuries, even after the
  draft-removal fix below.** Real cause: `AFCM_SIM_UI_activeLimb` is a plain missionNamespace var that
  never reset between separate dialog sessions, so the first limb-switch on a fresh open committed the
  on-screen form for whichever limb was active when the *last* session closed — before this session's
  real data had ever been loaded into the controls — silently overwriting the just-reloaded value with
  blank defaults. Fixed by resetting it at the top of every open. *(`de4afc3`, PR #52)*
- Injury Author's stale-reload bug, first pass: the dialog always preferred a per-unit "draft" saved
  unconditionally on every close over a fresh reload from the live unit, so injuries that changed after
  the first visit (e.g. combat damage, or a different training injury applied) never showed up on a
  later reopen. The whole per-unit draft mechanism was removed — edit mode now always reloads fresh.
  *(`a4b47ad`, PR #51)*
- Terminal-granted injury-edit permission could be given but never taken back. Added a mirrored "AFCM:
  Revoke Injury Editing" action (mutually exclusive with Authorize based on current state), and made
  the permission check re-read the CBA setting live instead of baking its value in at patient-spawn
  time. *(`a4b47ad`, PR #51)*
- MCI Creator's own patient-preset list wasn't reset after a spawn, so building and spawning a second,
  different incident silently reused the first incident's injuries even after clearing it via the
  Session Manager. *(`0c5b536`, PR #47)*
- Injury Author/MCI Creator UI polish: a mislabeled "Available Presets" text (it's actually in the MCI
  Creator, not the Injury Author) corrected to "Injury Presets"; Apply/Reset Patient button positions
  swapped on request; the Injury Author's live status readout now auto-starts right after Apply & Spawn
  Patient instead of requiring a manual "View Live State" click first. *(`0c5b536`, PR #47)*

**Added**
- **Zeus MCI Spawner redesigned.** Placing it used to spawn a blank batch of patients immediately and
  offer only one shared single-injury preset for the whole group via a scroll action. It now opens the
  real MCI Creator directly on the placing curator's own screen, with the module's placement position
  pre-filled as the location (its own "Choose Location on Map" step is skipped but still available to
  override) — per-patient preset assignment, including loading a real saved MCI Preset, not just one
  shared wound. Uses the same `local _logic` pattern Edit Injuries already uses so the dialog only
  opens on the placing curator's own screen. *(`5486c99`, PR #57)*
- Wound types expanded from 3 (Gunshot/Shrapnel/Blast) to 10, adding Abrasion/Avulsion/Contusion/
  Crush/Cut/Laceration/Thermal Burn — ACE3's full real `CfgWounds` taxonomy, grounded in a user-
  supplied ACE injury reference. The original 3 still go through ACE's probabilistic wound selection;
  the 7 new ones each apply their one exact real class deterministically via `addWound`. Contusion/
  Abrasion never bleed, matching ACE's own real base values regardless of what Bleeding was set to.
  *(`fd2f380`, PR #48)*
- Settable Blood Volume and SpO2 added to the Injury Author (edit mode only), via a new shared
  `setVitals` backend interface function implemented identically on both ACE/KAT compat addons.
  *(`2d91e9c`, PR #49)*
- Medical terminals can grant (and, as of the same-day follow-up fix above, revoke) injury-edit
  permission to a player — a new opt-in CBA setting, off by default so nothing changes for anyone who
  doesn't turn it on. *(`95a79fb`, PR #50)*

## 2026-09-28 (Eden AFCM Patient attributes actually working, marker/batch-spawn fixes, Injury Author draft race)

**Fixed**
- **Eden's "AFCM Patient" module attributes (Title/Casualty Type/Session Name) weren't visible in
  Eden at all**, despite being genuinely present and correctly resolved in the compiled config
  (confirmed by derapifying `config.bin`) — real, confirmed Eden behavior: the "System Specific"
  attribute panel doesn't walk a class's own inheritance chain, it only shows attributes declared
  directly in that class's own body, and these three lived on a shared base class the module inherited
  from. Fixed by flattening them directly into the module's own `Attributes` block. *(`7af10e0`)*
- **Those same attributes (and every other custom Eden/Zeus attribute in this addon) were never
  actually being written onto the placed object at all**, Title included — a custom attribute's
  `property=` only names the variable to use *if* something calls `setVariable`; the actual write
  needs an explicit `expression=`, confirmed against Bohemia's own wiki and a real RPT test showing
  all 6 attributes reading back `<NOT SET>` regardless of what was visibly set in Eden. Fixed by
  adding `expression=` to every attribute in both `eden/config.cpp` and `zeus/config.cpp`.
  *(`e4676b7`, `dad558a`; diagnosed via `124e478`/`0e2db9a`)*
- A combo attribute's value arrives at its own `expression` as a string, not the numeric `value=` its
  `Values` entries declare — fixed with `parseNumber` on Casualty Type/Training Preset/Patient Count.
  *(`d50599a`)*
- "Only one patient spawning" from a configured Spawn Marker Name, in two parts: the field was being
  treated as a single prefix the whole marker name had to start with, when the real value was a
  natural comma-separated list — fixed by splitting and matching each name exactly. *(`1b7450d`)*
  Then: the *on-demand* (synced-object) spawn path ignored Spawn Marker Name entirely and always
  spawned exactly one patient at the synced object's own position — fixed by sharing the same
  marker-resolution logic between the auto-spawn and on-demand paths. *(`c207688`)*
- **Injury Author dialog state could corrupt across different units.** Using "Edit Injuries" on a
  second unit while the dialog was still open on a first one raced the first instance's own close
  (which snapshots staged state as that unit's draft) against the second instance's own setup —
  whichever ran last won, so either unit's saved draft could end up holding the other's data. Fixed by
  closing any already-open instance first and deferring the rest of the open a frame. *(`023ecc2`, PR
  #42)*

**Added**
- Marker-based spawns are now exact-positioned (no jitter) rather than nudged ±2m like a shared random
  spot — a placed marker is a mission builder's deliberately exact spot. The synced-object "Spawn
  Patient" interaction also stopped disappearing permanently after one use (a 2s debounce instead of a
  one-shot lock), so the same configured scenario can be spawned repeatedly from the same object.
  *(`68ebfb2`)*

  obstruction/occlusion states — SpO2 is a real, different concept, not a stand-in for those.
  *(`fd72dad`, PR #34, open)*
- **"Stable" and "Bleeding Status" added to the live status readout** — both ACE3's own real,
  whole-unit classifications (`ace_medical_fnc_isInStableCondition`; a real No/Slow/Moderate/
  Severe/Massive Bleeding scale ACE's own medical GUI uses internally but never exposed as a
  reusable function, so it's recomputed here from the same two internal calls that GUI logic uses).

  bleeding so it doesn't under-report. *(`460ebec`, PR #33)*

**Fixed**
- **Reopening the Injury Author dialog no longer hides an already-applied injury.** Real cause: it
  always opened on the "chest" limb regardless of which limb actually had anything staged — the
  data itself was fine, you just weren't looking at the right limb. Now opens on the first limb
  (head/chest/arms/legs order) that actually has something staged, falling back to chest only when
  nothing does. *(`9078a4b`, PR #32)*
- **A real, visible `AFCM_SIM_CasualtyTypeAttributes.model` config error at the main menu**, not
  just RPT noise as previously assumed — the class had no base class at all, so it had no `model`
  anywhere in its inheritance chain; `scope = 0` only hides a class from the Zeus/Eden object
  browser, it doesn't exempt it from the engine's own config validation. Fixed by giving it
  `: Module_F`, matching every other real module class in these files.
- **Injury Author navbar hover, for real this time.** The previous fix killed native hover/focus
  entirely to stop a false-highlight bug, which also broke the active limb's own reliable

  skipped on the already-active one so there's no flicker. *(`416f296`, PR #31)*

**Docs**
- Added an external "Bandages Gloss up" reference spreadsheet (bandage effectiveness, bleed-rate/

- `INJURY_CODES.md`, `ACE_COMPAT.md`, `KAT_COMPAT.md`, `DESIGN.md`, and `addons/README.md` all

  same patient (or the same in-progress new-patient authoring session) — backing out to check
  something else no longer silently drops unapplied work. Independent of the existing "Remember
  Last-Used Injuries" setting, which is a separate, profileNamespace-backed convenience that
  persists only what was actually applied, across missions/restarts. *(`0d72dd6`)*
- **Injury Author dialog** — replaces the old two-screen limb-select + injury-editor flow with one
  dialog: a persistent left-side limb navbar (Head/Chest/L Arm/R Arm/L Leg/R Leg) next to a single
  injury-configuration form, so switching limbs never leaves the dialog — the old flow needed a
  separate limb-select screen and broadcast one shared wound to every selected limb identically,
  with no way to give different limbs different injuries without repeating the whole loop per limb.
  Injuries are staged, not applied immediately — the navbar commits the current limb's form before
  switching, so nothing is lost moving between limbs. Serves two real modes: editing an
  already-spawned patient ("AFCM: Edit Injuries", or dragging `AFCM_SIM_ModuleEditInjuries` in
  Zeus) pre-loads that unit's current injuries/KAT extras, Apply commits the whole staged set in

  setting is on), "Apply & Spawn Patient" builds it and spawns, disabled until a location is
  chosen via the reused Map Picker. Bleeding is a 5-option severity combo now (None/Light/Medium/
  Heavy/Severe — later redone as None/Small/Medium/Large, see above), not a checkbox — a real
  chosen bleed rate instead of a hidden random roll, fully backward compatible with older
  4-element preset/export data. WoundType gains a "None" option — explicit "no injury on this
  limb." Export/Import/Load Preset/Save Preset/Clear All/Random Damage (new — rolls a fresh injury
  set at Easy/Medium/Hard/Insane) all work identically in both modes. Also fixed a real native-Arma
  "flashing" bug on the last-clicked button (a focus/hover color mismatch), dialog-wide, not just

**Fixed** *(a full-codebase review pass, later the same day — merged 2026-09-03 as PRs #4-11)*
- **`applyInjury` now dispatches via `CBA_fnc_targetEvent`** to satisfy ACE3's real `local _unit`
  requirement on `ace_medical_fnc_addDamageToUnit` — previously called unconditionally from the
  server, so injuring a unit not local to it (most notably a live player-controlled casualty) could
  silently no-op while the UI kept reporting success. Also folded `ace_compat`/`kat_compat`'s
  previously byte-for-byte-duplicated `applyInjury` logic into one shared handler. *(`4149686`)*
- **Pneumothorax locality dispatch** — same real fix as above, applied to
  `handleBreathing`/`updateInternalBleeding` — plus a **Simple Pneumothorax severity bug**: it was
  getting the same severity (4) as Hemo/Tension, contradicting the continuous `_pneumothorax/4`
  scaling this addon's own code already used elsewhere. Now 2 for Simple, 4 for Hemo/Tension.
  *(`0de2c4e`)*
- **KAT Reset Patient now clears Fracture/Pneumothorax/Airway too** — `ace_medical_fnc_fullHeal` has
  no knowledge of AFCM's own KAT-specific variables, so a patient given a fracture then Reset kept
  showing it in the live status readout forever after. *(`9f81f21`)*
- **4 small correctness bugs**: Map Picker's pending pick wasn't cleared on Cancel/Escape, only
  Confirm, so a stale rejected position could get silently committed later; MCI Creator's Patient
  Count combo only ever listed 1-10, so a loaded preset with more patients showed a stale number
  that could silently discard already-configured patients if touched; the Confirm dialog's stashed
  message/yes-code were cleared *after* calling the yes-code, breaking a Yes-handler that itself
  opens a second confirm dialog; `spawnPatient` had no `isNull` check after `createUnit`, letting a
  failed spawn thread `objNull` into shared session-tracking state. *(`c1d86ae`)*
- **3 Medical Tent edge cases**: zero synced stretchers registered silently with no diagnostic; a
  stretcher destroyed mid-mission left a stale entry every future check kept running `distance`
  against; a session whose every patient died before treatment stayed "pending" forever with no way
  to resolve. *(`8fb89ac`)*
- **Interactive Terminal locality race** — `attachedTo _logic` (the Zeus attach path) isn't
  guaranteed to have replicated to the server yet when the callback first runs on a dedicated
  server; deferred 1s to match `spawnPatient`'s own reasoning. Also: `removeInjury` now propagates
  its callee's real return value instead of always reporting success once any function existed to
  call; `resolveMciPatientSpec` now logs when a referenced preset id can't be found instead of
  silently spawning an uninjured "casualty." *(`f82ccde`)*
- **Eliminated session/preset id collision risk** — `diag_tickTime + random 100000` had a real,
  small chance of two calls landing in the same tick and generating an identical id, silently
  merging two Spawn Sessions or overwriting an unrelated saved preset. Replaced with a simple
  always-incrementing counter per id type — guarantees no collision is possible at all. *(`7a98568`)*
- **`profileNamespace` preset data is now validated on read, not trusted blindly** — a hand-edited
  `.Arma3Profile` or disk corruption could leave a malformed entry behind, and every consumer did an
  unguarded `_x select 0` on it — one bad entry used to break reading, saving, deleting, *and*
  importing presets simultaneously. Now filtered out at the one source every getter reads through,
  so a bad entry is dropped and self-heals on the next write instead of staying permanently wedged.
  *(`3996fb7`)*
