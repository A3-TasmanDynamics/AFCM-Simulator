# Changelog — v0.1.0

Every addon still reports `version = "0.1.0"` (`CfgPatches`, all ten PBOs) — no version bump or
tag has been cut yet, so this file covers the whole of development to date under that one version.
Entries are sourced directly from the real git history (`git log`), newest first, one section per
day of activity. When a later version ships, it gets its own `vX.Y.Z.md` file in this folder.

---

## 2026-09-05

**Added**
- **Injury Author dialog** — replaces the old two-screen limb-select + injury-editor flow with one
  dialog: a persistent left-side limb navbar (Head/Chest/L Arm/R Arm/L Leg/R Leg) next to a single
  injury-configuration form, so switching limbs never leaves the dialog — the old flow needed a
  separate limb-select screen and broadcast one shared wound to every selected limb identically,
  with no way to give different limbs different injuries without repeating the whole loop per limb.
  Injuries are staged, not applied immediately — the navbar commits the current limb's form before
  switching, so nothing is lost moving between limbs. Serves two real modes: editing an
  already-spawned patient ("AFCM: Edit Injuries", or dragging `AFCM_SIM_ModuleEditInjuries` in
  Zeus) pre-loads that unit's current injuries/KAT extras, Apply commits the whole staged set in
  one request; authoring a brand-new patient with no live unit yet (new **Ctrl+Shift+I** keybind)
  starts empty (or restored from the last-used set if the new "Remember Last-Used Injuries" CBA
  setting is on), "Apply & Spawn Patient" builds it and spawns, disabled until a location is
  chosen via the reused Map Picker. Bleeding is a 5-option severity combo now (None/Light/Medium/
  Heavy/Severe), not a checkbox — a real chosen bleed rate instead of a hidden random roll, fully
  backward compatible with older 4-element preset/export data. WoundType gains a "None" option —
  explicit "no injury on this limb." Export/Import/Load Preset/Save Preset/Clear All/Random Damage
  (new — rolls a fresh injury set at Easy/Medium/Hard/Insane) all work identically in both modes.
  Also fixed a real native-Arma "flashing" bug on the last-clicked button (a focus/hover color
  mismatch), dialog-wide, not just here. *(`5e3d18b`, merged as PR #16)*

## 2026-09-04

**Added**
- **AFCM Patient module (Eden)** becomes a real building block for hand-authoring a custom MCI one
  patient at a time: a new "Injury Preset (paste to import)" attribute spawns the patient
  pre-configured from an exported Preset/Patient State string instead of clean/unconscious, and new
  "Spawn at Synced Object"/"Spawn Marker Name" attributes control where it spawns. A new "Export
  Patient State" scroll action on every spawned patient copies its current AFCM-applied injuries to
  the clipboard as a reusable string, tracked at the one real choke point every injury application
  already goes through. *(`eeccd2e`)*
- **KAT extras + cardiac state now included in patient state export/import** — previously only base
  ACE-style injuries were captured; fracture/pneumothorax/airway/cardiac rhythm were silently
  dropped since the Preset format never carried them. Extends the Preset shape with a new optional
  `katExtras` element, omitted entirely when everything's at its clear default. *(`811ed50`, both
  merged as PR #15)*
- **Eden module list trimmed** to just AFCM Patient + Interactive Terminal — AFCM MASCAL Zone, AFCM
  MCI Spawner (Eden), and Medical Tent removed outright (function files deleted, not hidden;
  Zeus's own MCI Spawner and the MCI Creator UI still cover live/ad-hoc batch spawning, but Medical
  Tent has no other entry point left anywhere in the mod now, since it never had a Zeus
  equivalent). *(`c57e924`)*
- **Export Patient State now outputs a bare injuries array** (e.g. `[["head","gunshot",0.25,
  false]]`) instead of the full Preset envelope — the id/name/author/description/tags fields were
  pure noise for the "export one patient, paste it into another module" workflow.
  *(`414a45c`)*

**Fixed**
- **AFCM Patient's sync-to-position bug** — a "Spawn at Synced Object" checkbox silently gated
  whether a synced object's position took effect at all, so simply syncing an object with the
  checkbox left at its default fell straight through to the module's own position. Checkbox
  removed; a synced object now always wins. *(`c57e924`)*
- Defensive trim + diagnostic logging on AFCM Patient's Injury Preset Import attribute.
  *(`1316368`)*

> `c57e924`/`414a45c`/`1316368` stayed on the feature branch after PR #15 merged early (see below);
> a follow-up PR #16 on 2026-09-05 caught `main` up on all three, alongside the Injury Author
> dialog above.

## 2026-09-01

**Added**
- **Medical Tent** — session-scoped treatment-completion detection built on top of Spawn Sessions.
  `AFCM_SIM_ModuleMedicalTent` (Eden): sync any stretcher objects from a mission maker's own
  composition to it (AFCM spawns no tent/scenery of its own). A Spawn Session resolves once every
  live patient in it is both **treated** (auto-detected via live medical state, or manually via a
  new "Mark as Treated" action) and within **Stretcher Radius** of a synced stretcher — one shared
  server-side monitor loop covers every placed tent at once, so multiple simultaneous tents/sessions
  resolve independently. Resolution shows a new custom AFCM-branded **toast** notification
  (`RscTitles`/`cutRsc` — a passive HUD overlay that never steals input focus from Zeus, unlike a
  dialog) and republishes `session.resolved` on the UI event bus for a mission's own AAR/scoring
  logic to subscribe to. *(`a81d584`)*
- **Interactive Terminal** module (`AFCM_SIM_ModuleInteractiveTerminal`, Eden/Zeus) — sync it (or
  drag it directly onto an object in Zeus) to any placed object, e.g. a Laptop, and every player
  gets two real scroll actions on it: "AFCM: Open MCI Creator" / "AFCM: Open Session Manager" — a
  diegetic way into the tool kit for a training scenario that doesn't need the CBA keybind or Zeus
  itself. *(`cc721f3`)*
- **Zeus "Edit Injuries" module** (`AFCM_SIM_ModuleEditInjuries`, `curatorCanAttach = 1`) — drag it
  directly onto any unit to open the Injury Editor immediately, reaching units that never got the
  "Edit Injuries" scroll action (only AFCM-spawned patients get that). Grounded in ACE3's own Zeus
  "Heal" module pattern (`attachedTo _logic` for the target, a `local _logic` guard so the dialog
  opens only on the placing curator's machine, then self-deletes). *(`0492d9b`)*

**Fixed** *(a full-codebase review pass, later the same day — merged 2026-09-03 as PRs #4-11)*
- **`applyInjury` now dispatches via `CBA_fnc_targetEvent`** to satisfy ACE3's real `local _unit`
  requirement on `ace_medical_fnc_addDamageToUnit` — previously called unconditionally from the
  server, so injuring a unit not local to it (most notably a live player-controlled casualty) could
  silently no-op while the UI kept reporting success. Also folded `ace_compat`/`kat_compat`'s
  previously byte-for-byte-duplicated `applyInjury` logic into one shared handler. *(`4149686`)*
- **Pneumothorax locality dispatch** — same real fix as above, applied to
  `handleBreathing`/`updateInternalBleeding` — plus a **Simple Pneumothorax severity bug**: it was
  getting the same severity (4) as Hemo/Tension, contradicting the continuous `_pneumothorax/4`
  scaling this addon's own code already used elsewhere. Now 2 for Simple, 4 for Hemo/Tension.
  *(`0de2c4e`)*
- **KAT Reset Patient now clears Fracture/Pneumothorax/Airway too** — `ace_medical_fnc_fullHeal` has
  no knowledge of AFCM's own KAT-specific variables, so a patient given a fracture then Reset kept
  showing it in the live status readout forever after. *(`9f81f21`)*
- **4 small correctness bugs**: Map Picker's pending pick wasn't cleared on Cancel/Escape, only
  Confirm, so a stale rejected position could get silently committed later; MCI Creator's Patient
  Count combo only ever listed 1-10, so a loaded preset with more patients showed a stale number
  that could silently discard already-configured patients if touched; the Confirm dialog's stashed
  message/yes-code were cleared *after* calling the yes-code, breaking a Yes-handler that itself
  opens a second confirm dialog; `spawnPatient` had no `isNull` check after `createUnit`, letting a
  failed spawn thread `objNull` into shared session-tracking state. *(`c1d86ae`)*
- **3 Medical Tent edge cases**: zero synced stretchers registered silently with no diagnostic; a
  stretcher destroyed mid-mission left a stale entry every future check kept running `distance`
  against; a session whose every patient died before treatment stayed "pending" forever with no way
  to resolve. *(`8fb89ac`)*
- **Interactive Terminal locality race** — `attachedTo _logic` (the Zeus attach path) isn't
  guaranteed to have replicated to the server yet when the callback first runs on a dedicated
  server; deferred 1s to match `spawnPatient`'s own reasoning. Also: `removeInjury` now propagates
  its callee's real return value instead of always reporting success once any function existed to
  call; `resolveMciPatientSpec` now logs when a referenced preset id can't be found instead of
  silently spawning an uninjured "casualty." *(`f82ccde`)*
- **Eliminated session/preset id collision risk** — `diag_tickTime + random 100000` had a real,
  small chance of two calls landing in the same tick and generating an identical id, silently
  merging two Spawn Sessions or overwriting an unrelated saved preset. Replaced with a simple
  always-incrementing counter per id type — guarantees no collision is possible at all. *(`7a98568`)*
- **`profileNamespace` preset data is now validated on read, not trusted blindly** — a hand-edited
  `.Arma3Profile` or disk corruption could leave a malformed entry behind, and every consumer did an
  unguarded `_x select 0` on it — one bad entry used to break reading, saving, deleting, *and*
  importing presets simultaneously. Now filtered out at the one source every getter reads through,
  so a bad entry is dropped and self-heals on the next write instead of staying permanently wedged.
  *(`3996fb7`)*

## 2026-08-30 (Spawn Sessions + MCI Creator hardening)

**Added**
- **Spawn Sessions** — every batch of patients spawned together (a Zeus/Eden MCI Spawner, an MCI
  Creator incident, an AFCM MASCAL Zone) is now grouped into a named session
  (`[id, label, spawnTime, units]`, `AFCM_SIM_spawnSessions`), independent of the existing flat
  patient list. New **Session Manager** dialog lists sessions and deletes one at a time without
  touching any other session's patients (e.g. two medics each working their own MCI at once); a new
  generic, reusable **Confirm dialog** (Yes/No) gates the one remaining fully-destructive action,
  "Clear All Sessions." Bound to a new CBA keybind, default Ctrl+Shift+O. *(`92b93a6`)*
- **Optional custom session names** — every batch spawn path (Zeus/Eden Spawn Patient, MASCAL Zone,
  MCI Spawner, and the MCI Creator dialog) now accepts a free-text label overriding the
  auto-generated one when non-blank, via a shared `AFCM_SIM_SessionName` Eden Attribute
  (`control = "Edit"`) or a matching field on the MCI Creator. *(`e1faf99`)*
- A real marker now drops on the Map Picker at the spot you click, so the pick is visually
  confirmed before spawning. *(`b26e023`)*
- MCI Creator: multi-limb toggle-select + apply in the injury editor, and patient count 1–10.
  *(`739e82f`)*
- **MCI Creator** — a standalone tool: pick a patient count, assign each patient its own Injury
  Preset (or "random") independently, pick a spot on a real interactive map
  (`RscMapControl`-based Map Picker), spawn the whole incident in one request. *(`45bf860`)*
- **MCI Spawner** modules (Zeus + Eden) — spawn a batch of patients and apply one Injury Preset to
  the whole group at once; injury editor gained a Back button. *(`a10db6b`)*
- **Injury Presets** — create, save, apply, export, and import named injury configurations, built-in
  + a per-player `profileNamespace` user library. *(`8a5e301`)*
- Real KAT-specific **Fracture/Pneumothorax** injuries, wired into the injury editor. *(`cf63e00`)*
- Configurable **Casualty Type** (clothing/appearance) on every spawn path, and patients now spawn
  stripped to bare clothing. *(`d5274c5`)*
- Backend-aware injury editor — real ACE/KAT wound-type selections, KAT-only controls shown only
  when KAT is the active backend. *(`0a771a8`)*

**Fixed**
- KAT Fracture restricted to arms/legs only (not head/chest — KAT's own array has slots for both,
  but this project deliberately excludes them). *(`a0dc9f3`)*
- MCI Eden preset-injuries type mismatch (raw Array vs. required Injury HashMap) and a missing
  module re-fire guard. *(`c85b10f`)*
- UI dialogs re-centered on screen; Reset split into per-limb (local, non-destructive) and
  per-patient (full reset) actions. *(`7f3ef44`)*
- **Patients healing themselves — real root cause found and fixed**: engine `setUnconscious` was
  fighting ACE's own `ACE_isUnconscious` tracking. Redesigned the affected UI dialogs at the same
  time. *(`5c2810f`)*
- Reverted a brief 13-region `LimbId` experiment back to the original 6 values (a direct 1:1 match
  to ACE3's real body parts) after `0a771a8`/`19148c4` explored KAT-only controls. *(`039b578`)*
- Reverted a recurring unconscious-lock safeguard; injury editor's wound-type list went back to
  ACE-only pending further work. *(`19148c4`)*
